# PySpark ETL Application Instructions

This document describes how to initialize and run the ETL lab, either by bringing up the development environment locally (configuring environment variables) or by using Docker Compose.

## Prerequisites
- Install **Python 3.12** (if you intend to run it locally).
- Install **Docker and Docker Compose** (for containerized execution).
- Have the `.env` file ready and configured with your RapidAPI credentials. You can use the `.env.example` file as a base.

## Initial Setup

Before proceeding with either option, make sure to create and configure your `.env` file:

```bash
cp .env.example .env
```
Edit the `.env` file and add the actual value of your `API_KEY` associated with the "Currency Conversion and Exchange Rates" API from RapidAPI.

---

## Option 1: Run the development environment locally (Without Docker)

To run the application in your local environment, you need to load the credentials from the `.env` file into the system's environment variables, and then execute the scripts.

1. **Install dependencies**
   Make sure to install the required libraries by running the following in your terminal:
   ```bash
   pip install -r requirements.txt
   ```

2. **Export environment variables**
   Export the variables defined in your `.env` to your terminal's current session:
   ```bash
   export $(grep -v '^#' .env | xargs)
   ```
   *(Note: This command will read every line of the `.env` that is not a comment and export it to your Linux/macOS shell environment).*

3. **Fetch the data**
   Run the extraction script that will consume the API to get the currency exchange rates and simulate the sales data.
   ```bash
   python fetch_data.py
   ```
   *This will generate the `sales.csv` and `rates.json` files inside the `data/` folder.*

4. **Run the ETL Pipeline**
   Run the processing pipeline using PySpark.
   ```bash
   python etl_pipeline.py
   ```
   *The pipeline will enrich the data and write the result to the `data/enriched_sales` folder using the Parquet format.*

## Option 2: Run the application using Docker

The project is ready to spin up a Spark cluster (consisting of a Master and a Worker node) as well as a container designed to run the application via `docker-compose.yml`. In this option, Docker automatically injects the variables from the `.env` file into the container, so **you don't need to export them in your host system**.

1. **Bring up the containers**
   To build the Python image and start the complete Spark environment over the background, run:
   ```bash
   docker compose up --build -d
   ```

2. **Verify the containers**
   If you use the `docker ps` command, you will see three containers running in your local network: `spark-master`, `spark-worker`, and your `etl_app` application. You can also access the Spark Master web interface at `http://localhost:8080`.

3. **Run the scripts inside the ETL container**
   Since the containers are up and the project folder is mounted as a volume, you can launch the scripts through the application container.

   First, extract and generate the fake data:
   ```bash
   docker compose exec etl_app python fetch_data.py
   ```

   Second, run the ETL pipeline (your cluster will process the task and write the updated Parquet files):
   ```bash
   docker compose exec etl_app python etl_pipeline.py
   ```

4. **Stop the environment**
   Once the work is done, you can tear down the containers by running:
   ```bash
   docker compose down
   ```

## Output Data Explanation (`data/enriched_sales`)

The `data/enriched_sales` directory is automatically generated by Apache Spark at the end of the `etl_pipeline.py` script execution during the **Load** phase. It contains your final data product: the sales enriched with currency exchange rates. 

Instead of a simple `.csv` file, Spark uses a distributed structure, so you will find the following files inside:

1. **`_SUCCESS`**: An empty file automatically generated by Spark when the write is complete. Its sole purpose is to indicate safely that the entire process finished successfully and the data is not corrupt.
2. **`part-00000-...snappy.parquet`**: This is the actual file containing the data. 
   - **`.parquet`**: A highly optimized columnar storage format for analytics (Big Data). Unlike a CSV file, it stores metadata, exact data types for each column, and compresses the data to make large-scale processing much more efficient.
   - **`.snappy`**: The default compression algorithm used by Parquet to reduce file size without significantly impacting decompression speed.
   - **`part-00000`**: Indicates that your Spark cluster processed the data in 1 partition (normal for small data). If you processed large amounts of data, Spark would create multiple parts (`part-00001`, `part-00002`...) to allow for very fast parallel reading.
3. **Hidden `.crc` files**: These are checksum files used by Hadoop/Spark internally to verify data integrity and ensure no bits were corrupted on the disk.
